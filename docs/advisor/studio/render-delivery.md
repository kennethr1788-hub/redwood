# Present rendering and delivery

TOPIC: studio.render-delivery
PURPOSE: Explain stale output and separate local rendering, review, export and publication.
WHEN TO USE: Stale/unknown render, failed or interrupted output, readiness, covers, CTA or delivery questions.
REQUIRED FACTS: Current saved revision; owner-reported freshness; available render/output observations; edits since render; intended destination and review evidence.

STABLE PRINCIPLES
A Present render is tied to a saved source, timeline, revision and output binding. If relevant content changed, old output cannot prove the current edit. The owner also checks output identity; STALE alone does not identify exactly which edit or missing/hash-changed file caused it. A stale render alone does not establish timeline loss. Preserve the original and saved work; inspect actual existence and freshness before making preservation claims.

DECISION TREE
Read the current revision/status. If STALE, inspect the saved timeline, existing render job and outputs before rerendering. If the latest render is evidenced as older, explain the mismatch; never invent its revision when not supplied. If a job is running/unknown, reconcile it instead of starting a duplicate. Once the desired edit is confirmed, the user can render from Present and inspect the resulting video. An old export can remain a historical artifact without being current or ready to publish.

Final playback review includes beginning/end, click-to-result continuity, readable UI, captions, audio and both intended ratios. Inspect the cover at small size and choose a settled frame showing honest proof. Match one useful CTA to the demonstrated promise; Present's fixed closing footer is not a custom clickable end-card editor.

Present currently exports landscape/portrait H.264 MP4 plus supported local artifacts such as covers and subtitle sidecars. There is no general resolution/format picker or hosted publishing step. A local export is not platform acceptance, and acceptance is not publication. Read actual output metadata and preview it at the intended destination; a filename alone does not prove encoding or accessibility.

COMMON FAILURE MODES
Blind rerender, deleting old output before inspection, treating RENDERED as INSPECTED, claiming a share folder is hosted, or borrowing ads safe-zone rules for organic delivery. Official placement/account rules outrank teacher recipes.

STOP CONDITIONS: Unknown running job, stale source/output, missing rights, unreadable proof, unreviewed final playback or unverified destination constraints. Advisor never renders, uploads, publishes or spends.
WHAT NOT TO CLAIM: Automatic quality approval, a universal platform preset, unseen output integrity, or publication from export.
