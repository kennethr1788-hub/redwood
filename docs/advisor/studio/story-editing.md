# Present story and editing

TOPIC: studio.story-editing
PURPOSE: Help one viewer understand one useful outcome with the least necessary footage.
WHEN TO USE: Boring/confusing demos, openings, pacing, proposed cuts or creative deconstruction.
REQUIRED FACTS: Intended viewer; promised outcome; supplied observations of the actual recording; meaningful action/result; retained source intervals; what must remain true.

STABLE PRINCIPLES
Make the promise, opening and demonstrated proof agree. Reduce irrelevant material and direct attention to the useful change. A product-demo story needs enough problem context to make its action and result understandable. Label synthetic data and shortened waits honestly. No universal magic-second opening, cut length or retention uplift follows from these principles.

DECISION TREE
If the demo feels boring, identify whether the constraint is unclear purpose, delayed evidence, unreadable proof or unnecessary waiting. Do not cut the first five seconds merely because a rule says so. Ask what the viewer learns in each interval. Preserve the click-to-result relation, meaningful error/loading feedback and time to read the outcome. Try one opening/cut change, then watch at normal speed and test comprehension.

Present supports trimming and removing/restoring source intervals, including reviewed aligned-word and low-amplitude proposals. It does not provide arbitrary clip reordering, freeze-frame insertion, speed ramps or a transition picker. If a useful hold needs more time, restore existing source if available or rerecord it. Silence is not proof the visuals are disposable; a caption gap is not proof of silence. Review sound and meaning around every cut.

Creative deconstruction is a hypothesis worksheet: observed pattern → purpose → alternative explanation → original adaptation → one variable to test. Compare examples with an appropriate baseline, keep attribution/asset rights, and distinguish public attention from causal proof or profit. Do not copy scripts or import a scraping/example database.

COMMON FAILURE MODES
Decorative motion before a coherent story; hiding a real confirmation step; implying edited waits are actual product latency; removing every pause; inventing footage/control availability; calling one teacher heuristic a platform rule.

STOP CONDITIONS: No recording observations, unsupported control, missing proof/rights or a change that would misrepresent behavior. Advisor has no frames/audio unless explicitly supplied; current project status alone does not show whether a demo is boring.
WHAT NOT TO CLAIM: Viral guarantees, measured attention gains, publication, or media inspection not performed.
NEXT ACTION / OUTPUT SHAPE: Viewer/outcome; observed constraint versus hypothesis; one preserved invariant; one edit or recording recommendation; playback acceptance.
