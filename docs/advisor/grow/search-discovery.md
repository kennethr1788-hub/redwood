# Grow search and discovery

TOPIC: grow.search-discovery
PURPOSE: Choose one evidence-backed search/content improvement without promising rankings.
WHEN TO USE: SEO, AEO/AI search, page/topic priorities, crawl/index questions or search-report interpretation.
REQUIRED FACTS: Owned page and revision; existing versus proposed status; user task/query evidence; content/claim sources; crawl/index observations; report scope and filters.

STABLE PRINCIPLES
Fix access, intent and factual usefulness before cosmetic optimization. Give each page a distinct useful purpose, a descriptive title/heading and relevant internal links. Avoid many thin pages repeating the same answer. A proposed page does not exist until the owner creates it. A sitemap helps discovery but does not guarantee indexing; crawler controls are not access security.

DECISION TREE
Does the relevant page exist? If not, mark it PROPOSED and establish a distinct unmet user task. If it exists, inspect actual access/index evidence, contradictory directives or duplicate/canonical problems, content/task match, internal discovery and mobile usability. Select the smallest change with a verifiable user benefit. Observe comparable reports afterward rather than inventing traffic estimates.

For AI search, separate established search foundations from provider-specific current guidance and experimental visibility hypotheses. Accurate explicit product/entity facts and readable answers serve users; they do not guarantee model citations. No universal AI ranking score, magic answer length, special markup or new crawler infrastructure is established here. Search crawling, model training and user-triggered retrieval can have different controls; recheck the exact provider purpose before changing access settings.

Structured data must describe visible supported facts and an actually supported feature. Do not prescribe retired rich-result features from an old playbook. Search result presentation and report availability can change. Grow does not automatically possess every Search Console or AI-report diagnostic; a bounded imported CSV cannot prove whole-site coverage.

COMMON FAILURE MODES
Low CTR called a bad title without intent/device/rank context; missing data relabeled zero; canonical treated as an unconditional command; one model-answer screenshot treated as durable ranking; unsupported claims repeated as expertise; a three-route audit called complete site coverage.

STOP CONDITIONS: Unowned/private data, contradictory directives, missing content, unsupported structured data, incomparable reports or a change requiring source access outside the available owner scope. Advisor can prepare a Build task; it cannot crawl, edit robots rules or publish pages.
WHAT NOT TO CLAIM: Rankings, indexation, search volume, guaranteed AI citations, causal uplift or current private property eligibility.
NEXT ACTION / OUTPUT SHAPE: Page status; observed blocker; evidence versus visibility hypothesis; one useful improvement; required owner check and observation window.
SOURCE STATUS: Distribution guidance. Owner source paths are indexed in knowledge.mjs; internal maintenance provenance is not distributed or verified by the public suite.
LAST VERIFIED: 2026-10-04 research snapshot. RECHECK TRIGGER: Platform/report/crawler or page revision changes, conflicting evidence, feature retirement, or any proposed access-control change.
